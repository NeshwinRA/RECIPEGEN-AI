# RecipeGen AI: Overview

> FROZEN FILE. Do not edit. If something here is wrong, tell the user.

## What this is
An AI cooking assistant: the user enters ingredients and preferences, the app returns a validated recipe generated by Google Gemini, optionally grounded by retrieval (RAG) from a recipe dataset in ChromaDB. History and favourites are stored in SQLite. Deployed publicly for recruiters.

Target audience (set by the owner): bachelor men, with a South Indian food focus. This shapes the defaults: quick recipes, few utensils, pantry ingredients, South Indian regional styles.

## Architecture (single Streamlit + Python app, no separate backend)
```
User input -> Streamlit -> validation -> [optional RAG retrieval from ChromaDB]
-> prompt builder -> Gemini API -> response parsing -> response validation
-> [optional SQLite save] -> display
```

## Risks (read these)
1. **Python 3.14.3.** ChromaDB and the torch dependency of sentence-transformers may not have working wheels for a version this new. I cannot verify current package support. Use Python 3.12 for the venv unless F01 proves 3.14 works.
2. **Gemini free tier limits.** Rate limits will slow the evaluation run (about 60 API calls minimum). Build in sleeps and retries. Check current limits in Google's docs.
3. **Dataset coverage.** A South Indian, bachelor-friendly focus only works if the dataset has enough such recipes. F14 must report this honestly.
4. **Diet validation is keyword-based.** It catches obvious errors only. It must be described that way in the README. Never call output "guaranteed vegetarian" or "safe".
5. **Food-safety disclaimer** must appear in the app and README.
6. **Deployment memory.** Sentence-transformers + ChromaDB may exceed a free host's limit.
7. **Secrets.** One committed API key means rotating it. F32 exists for this.
